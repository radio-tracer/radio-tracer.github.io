Where the idea comes from

In medicine and engineering, a radiotracer is a tiny probe you inject so you can see where something actually goes — not where a map says it might go.

Radio

The signal — a known CVE / vulnerable method from your SCA inventory. You choose what to watch; the agent does not invent CVE maps alone.

Tracer

The agent injects a lightweight probe at class load and reports when that method runs under your tests or app traffic — runtime evidence, not a graph guess.

~88%

SCA noise is real

Package scanners answer “is a vulnerable package on my tree?” They do not answer “did my app run the vulnerable code?” Teams drown in alerts that never fire on their workload.

Static reachability still misses reflection, DI, and frameworks. RadioTracer answers with a hit.

Package SCA is the inventory. Static graphs are the map. RadioTracer is the Geiger counter — if the vulnerable method runs, you hear it.

The product

Two tools. One reachability story.

RadioTracer is an umbrella: prepare a method-level watchlist from SCA, then prove which of those methods actually execute under your JVM workload.

Features

Built for signal, not noise

SCA tells you what’s on the tree. The importer builds the watchlist. The agent tells you what actually ran.

💉

Runtime probes

Lightweight Java agent instruments watchlist classes on load. No dependency JAR rewrites on disk.

🧪

CVE → method import

Companion radio-tracer-cve-import turns SCA output into a probeable methods.json watchlist.

🔴

REACHABLE on first hit

First invocation of a watched method logs instantly on stderr with stack — prioritize while the run is live.

📄

HTML report on exit

Multi-module fragments merge into one flat report with hit counts by CVE + method. CI-friendly artifact.

💬

Slack on first hit

Optional webhook: notify #security when a critical path lights up, plus an end-of-run summary.

🧩

SCA-agnostic

Bring any methods.json — generated by the importer or hand-written. Agent stays SCA-tool independent.

Support

Scanners & runtimes

The agent is SCA-agnostic at the methods.json boundary. The importer currently ships a Snyk path; more scanners are adapter work. Runtime coverage today is the JVM family — one agent for any language that runs as bytecode.

SCA scanners

  • Snyk Supported via radio-tracer-cve-import → methods.json
  • Trivy · OWASP DC · Dependabot · OSV Coming importer adapters (same methods.json shape)
  • Hand-written methods.json Supported any SCA · agent accepts the watchlist directly

Programming languages / runtimes

  • Java Supported -javaagent · ByteBuddy · JDK 21+
  • Kotlin Supported same agent · JVM bytecode
  • Scala · Groovy · Clojure Supported same agent when methods run on the JVM

Quick start

End-to-end · Snyk → agent → evidence

How you use RadioTracer on your app: download agent v0.2.0 from GitHub Releases, build a watchlist from Snyk, attach with -javaagent, run your tests or service. Multi-module Maven builds can share one report path — hits are merged flat by CVE+method.

e2e · radio-tracer-agent 0.2.0 + your app 
# ─────────────────────────────────────────────────────────────
# RadioTracer v0.2.0 — use on YOUR app
# Requires: JDK 21+, Snyk CLI, Python 3.11+ (for the importer)
# Release: https://github.com/radio-tracer/radio-tracer-java/releases/tag/v0.2.0
# ─────────────────────────────────────────────────────────────

# 1) Download the agent JAR from GitHub Releases (v0.2.0)
#    https://github.com/radio-tracer/radio-tracer-java/releases
#    (shaded agent · multi-module flat HTML merge · Slack optional)
curl -fsSL -o radio-tracer-agent.jar \
  https://github.com/radio-tracer/radio-tracer-java/releases/download/v0.2.0/radio-tracer-agent-0.2.0.jar

# 2) SCA scan your project (Snyk — currently supported importer path)
snyk test --json > snyk.json

# 3) Install the CVE importer, then build a method-level watchlist
#    https://github.com/radio-tracer/radio-tracer-cve-import
pip install "git+https://github.com/radio-tracer/radio-tracer-cve-import.git"
radio-tracer-cve-import \
  --source snyk \
  -i snyk.json \
  -o methods.json

# 4) Optional Slack on first REACHABLE + end-of-run summary
# export RADIO_TRACER_SLACK_WEBHOOK=https://hooks.slack.com/services/T…/B…/…
#    (or pass slack=… on the -javaagent= argument)

# 5) Attach the agent to YOUR app / integration tests / Spring Boot jar
#    Multi-module: use the same report= path (or report dir) across modules —
#    each JVM writes report.html.d/<label>-<pid>.json and merges a flat HTML.
java -javaagent:radio-tracer-agent.jar=\
methods=methods.json,\
report=./radio-tracer-report.html \
  -jar your-app.jar

#    Maven example (integration tests as the workload — prefer real call paths):
#    export MAVEN_OPTS="-javaagent:$PWD/radio-tracer-agent.jar=methods=methods.json,report=$PWD/radio-tracer-report.html,label=${project.artifactId}"
#    mvn -pl your-module verify

# 6) Evidence
#    · stderr: [REACHABLE] on first hit of a watched method (with stack)
#    · HTML report on JVM exit (flat multi-module merge when several JVMs share report=)
#    · Slack (if configured) on first hit + summary
#
# REACHABLE = prioritize under this run.
# No hit = not observed here — not “safe.”
